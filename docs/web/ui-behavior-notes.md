# Smaller UI decisions

Self-contained rationale that doesn't need its own page.

**Reader preferences reset** (`lib/stores/reader-preferences.ts`) — the Display popover's "Reset to defaults" calls `reset()`, which restores only `TYPOGRAPHY_DEFAULTS` (`fontSize`/`lineHeight`/`fontFamily`). It never touches `showTranslation`/`language`, which belong to the separate Translation control — a shared `DISPLAY_DEFAULTS` here would silently switch translations off from an unrelated button.

**Copy-paragraph feedback** (`components/reader/paragraph-block.astro`) — the 1.5s check-mark swap guards re-entry with a `data-copied` flag. Without it, a second click inside the feedback window captures the check-mark SVG itself as the "original" to restore to, leaving the icon stuck on the check-mark permanently.

**Single shared copy-actions toolbar** (`components/reader/reader-copy-actions.astro`) — the per-paragraph copy-link/copy-text buttons used to be rendered inline in every `paragraph-block.astro` instance. At ~450k paragraphs sitewide that markup (two buttons + inline SVGs, `aria-hidden="true"`) was duplicated ~450k times — roughly 450MB of the build, and un-reachable by keyboard/AT since it was marked `aria-hidden`. It is now a single instance mounted once in `pali-reader.astro`, relocated into whichever paragraph is hovered or focused (`pointerover`/`focusin` delegated on `[data-reader-article]`, DOM-reparented via `insertBefore` — not CSS-positioned, since its host paragraph changes). `data-visible` (a plain Tailwind data-attribute variant, not custom CSS) drives the opacity/pointer-events toggle. A `role="status" aria-live="polite"` element announces "Link copied" / "Paragraph copied" — there was previously no feedback for screen-reader users at all.
Trade-off, disclosed rather than silently shipped: because plain paragraph text has no natural keyboard tab stop, a keyboard-only user (no pointer) cannot Tab directly to an arbitrary paragraph's copy actions — there is exactly one shared toolbar, not 450k tab stops (450k sequential tab stops would itself be a worse keyboard experience than today). The underlying content need is still fully keyboard/AT-accessible without it: paragraph text is selectable and copyable via native text selection, and `id="para-N"` fragments are constructible from the address bar. `focusin`/`focusout` on the article does reveal and reposition the toolbar for a mouse-then-Tab interaction (hover to reveal, Tab to activate by keyboard instead of clicking), and once revealed its two buttons are real, labelled, focusable `<button>`s — no `aria-hidden` trap.

**Start-texts carousel** (`components/start-texts/start-texts-carousel.tsx`) — auto-advances every 7s but pauses on hover/focus and is skipped entirely under `prefers-reduced-motion`. Required by WCAG 2.2.2: moving content that lasts more than 5 seconds must be pausable.

**Unreachable node throw** (`pages/[...slug].astro`) — the `!node` branch can't actually happen (every slug comes from `getAllPaths`, which is also what `getStaticPaths` enumerates from), so it throws instead of redirecting to a fake `/404`. A build-time throw surfaces a corpus/build inconsistency immediately instead of shipping a broken page.

**Daily reflection** (`components/daily-reflection/daily-reflection.tsx`) — the index is derived from the UTC day number (`Date.now() / 86_400_000`), not `Math.random()`, so the passage is stable for the whole calendar day, matching the "Today's reflection" label. Server and first client render always show `REFLECTIONS[0]` (no date math in the committed markup); the real day's entry appears once `useHydrated()` flips (see [hydration-and-persistence.md](./hydration-and-persistence.md)).

**Reflection content is curated, not generated** (`components/daily-reflection/reflections*.ts`) — every Pāli passage and `href` must be copied verbatim from a real built page and verified to resolve. A misquoted or dead-linked verse is worse than none.

**Translation failure is visible, not silent** (`components/reader/reader-translations.tsx`) — a failed fetch used to just call `removeTranslations()`, leaving the toggle in the "on" state with nothing to show and no explanation. It now also renders a dashed-border notice in the article ("{Language} translation unavailable right now — showing Pāli only.") and announces it via a page-level `role="status" aria-live="polite"` div (created once, appended to `document.body`, reused across soft navs and islands). The same announcer reports successful loads too ("{Language} translation loaded."), including cache hits — toggling translation off/on again re-announces from the module-scoped cache.

**One `<main>` per page** (`components/corpus/corpus-layout.astro`) — its center content column used to be a second `<main>`, nested inside `layouts/Base.astro`'s page-level one. `<main>` must not nest (HTML spec) — the parity harness's `a11y-static` check caught this on every corpus page once `Base.astro` gained a skip-link target at `id="main"`. The column is a plain `<div>` now; `Base.astro`'s `<main id="main">` is the only landmark.

**Footer heading level** (`components/site-footer.astro`) — the three link-group headings ("Read"/"Study"/"For developers & AI") were `<h3>`, which skips `<h2>` on any page whose main content has no heading between the page's own `<h1>` and the footer (most TOC/collection pages, static pages). They're `<h2>` now — siblings of whatever heading level the main content happens to reach, not nested under it, since `<footer>` is its own landmark, not a continuation of `<main>`'s outline.

**No mobile off-canvas drawer for the corpus tree** (`components/corpus/corpus-layout.astro`, `components/corpus-browser-disclosure.astro`) — considered and rejected (M7.6). Mobile already has full functional coverage via the inline `<details>` disclosure (`CorpusBrowserDisclosure`, and the "On this page" `<details>` in `[...slug].astro`) rendered directly in the page flow; a drawer would be a third presentation of the same tree. A drawer is also a modal — it needs a focus trap, `inert` on the background, Escape handling, scroll lock, and a restore-focus contract, which is a meaningfully larger a11y surface than a disclosure widget. The panes' `client:media`-gated toggle buttons are simply unreachable below the breakpoint by design (see [hydration-and-persistence.md](./hydration-and-persistence.md)) — that's intentional, not a gap: at that viewport the aside itself is `display:none`, and the `<details>` disclosure is the mobile equivalent.

**Alpha-modified text colors and contrast** — computed WCAG ratios (OKLCH → sRGB, alpha-blended against the actual background/card tokens in both themes) found three real failures: the copy-actions icon buttons at `text-muted-foreground/60` (2.68:1 light — below the 3:1 non-text minimum), the translation attribution at `/70` (3.28:1 light, 4.42:1 dark — both below the 4.5:1 text minimum), and — found separately, by an actual Lighthouse run rather than the manual `grep` sweep that caught the first two — the paragraph-number label at `text-primary/80` (4.08:1 light, confirmed to the second decimal by Lighthouse's own measurement). All three now use full opacity, matching the `text-muted-foreground hover:text-foreground` pattern already used elsewhere (e.g. `pane-collapse-toggle.tsx`). `breadcrumbs.astro`'s `/50` separator chevron is unaffected — it's `aria-hidden="true"` and purely decorative (redundant with the list structure), which WCAG exempts from contrast requirements. Lesson for next time: grep for `/[0-9]` catches the color token you think to search for; a real rendered-page contrast audit catches the ones you didn't.

**Lighthouse `target-size` on the sidebar tree — known, not fixed** (`components/corpus-tree-node.astro`) — dense navigation links in the corpus browser sidebar are ~19px tall (WCAG 2.2 SC 2.5.8 Target Size (Minimum) wants 24px). This is WCAG **2.2**, not the WCAG 2.1 AA this project targets (`docs/10-delivery-accessibility-community/full-accessibility.md`) — SC 2.5.8 doesn't exist in 2.1. Fixing it properly means inflating row height throughout a component that's recursively used for a deep hierarchical tree, a real information-density tradeoff against a criterion not currently in scope; noted here rather than silently ignored, for if/when the target is raised to WCAG 2.2.
